# 高同质评论直接折叠提示词

你将收到一批已经通过相关性筛选的真实游戏评论。你的任务是只折叠语义上可以安全互换的高度同质评论，以缩短 JSON，同时完整保留编号追溯。

## 合并判定

只有讨论对象、具体方面、立场、核心判断和主要理由全部一致时才允许合并，并且还必须同时满足：

1. 没有成员增加独立事实、原因、建议、条件或反例；
2. 不存在反讽、指代不清或依赖上下文才能解释的歧义；
3. 任选组内一条作为代表时，不会改变该组对后续分析所表达的观点。

以下相似性不足以支持合并：

- 只属于同一话题或提到同一角色；
- 只有情绪方向相同；
- 都在询问“要不要抽”，但账号配置不同、预算不同；
- 抽取对象或替代选项不同；
- 一个询问适配性，另一个表达已经做出的决定；
- 结论相同但理由不同；
- 一条评论比其他成员多出具体机制、数据、建议或个人经历。

不确定时保持独立。压缩率不是目标，语义不失真才是目标。

## 输出

只输出一个 JSON 对象，不要 Markdown 代码块或解释文字：

```json
{
  "platform": "douyin",
  "comments": [
    {
      "record_id": "DY-0012",
      "text": "未经改写的真实代表原文",
      "support_count": 3,
      "merged_record_ids": ["DY-0012", "DY-0086", "DY-0147"]
    },
    {
      "record_id": "DY-0207",
      "text": "未经改写的独立评论"
    }
  ],
  "stats": {
    "input_count": 4,
    "output_count": 2,
    "folded_count": 2
  }
}
```

规则：

- 折叠组至少两条，`support_count` 等于 `merged_record_ids` 长度并包含代表自身；
- 代表编号必须属于成员，并选择最清楚、最完整表达共同观点的真实评论；
- `text` 必须逐字复制代表评论，不改写错别字、表情、标点或换行；
- 独立评论只输出 `record_id` 和 `text`；
- 每个输入编号恰好出现一次：作为代表、折叠成员或独立评论；
- 不跨平台折叠；
- 输出顺序按代表评论或独立评论在输入中的首次出现顺序；
- `input_count = output_count + folded_count`，其中 `folded_count` 是折叠后减少的记录数。

修正案例见 [fold-similar-comments-example.md](fold-similar-comments-example.md)。
